01 · 什麼是 Git

一台專案的時光機

沒有 Git 的時候，我們會存出「報告_最終版_真的最終_v3.docx」。Git 讓你只保留一份檔案，同時記得它所有的過去。

📸

記錄歷史

每次 commit 都會存下整個專案當下的樣子，附上時間、作者和說明。

⏪

隨時回溯

改壞了也不怕，可以比較差異，或回到任何一個過去的版本。怎麼做 →

🤝

多人協作

每個人在自己的電腦上工作，再把成果合併在一起，不會互相覆蓋。

02 · 三個區域

檔案的三段旅程

理解 Git 最重要的一步：檔案會依序經過三個地方。

1

工作目錄

Working Directory

你正在編輯的檔案，就是電腦裡看得到的那個資料夾。

git add→
2

暫存區

Staging Area

從改過的檔案裡，挑出「這次要存的」。沒挑到的檔案會留在工作目錄，等下次再存。

git commit→
3

儲存庫

Repository

正式存下快照的地方，藏在 .git 資料夾裡。

04 · 分支

          
開一條平行時間線

          
想試一個新功能，又怕弄壞原本能用的版本？開一個分支（branch）。在分支上的修改不會影響 main，確定沒問題後再合併（merge）回來。

          
    
            
  • git branch new-idea建立分支
    • 
            
  • git switch new-idea切換過去
    • 
            
  • git switch main回到主線
    • 
            
  • git merge new-idea把成果合併進來
    •

06 · 回溯

        
改壞了？三種回頭的方法

        
先想清楚你要退回的是「還沒存的修改」，還是「已經提交的版本」，再選對工具。

      

      

        

          安全
          
restore

          
還沒 commit 的修改不要了

          
git restore 檔名
git restore --staged 檔名

          
第一行把檔案改回上次提交的樣子；第二行把檔案從暫存區拿出來，內容不變。

          
⚠️ 第一行會丟掉還沒存的修改，救不回來。

        

        

          安全・推薦
          
revert

          
取消某一次已經提交的修改

          
git revert 提交編號
git push

          
新增一個「反向」的提交，把那次的修改抵銷掉。歷史紀錄都還在，已經推上 GitHub 也能放心用。

        

        

          危險
          
reset --hard

          
整個退回某個版本，之後的全丟掉

          
git reset --hard 提交編號

          
之後的提交和還沒存的修改都會消失。如果已經推上 GitHub，還得強制推送，很容易和別人衝突。

          
⚠️ 不確定的話，用 revert。

        

      

      

        
只是想「看看」舊版？

        
git checkout 提交編號 會讓資料夾暫時變成那個版本，這時 Git 會說你在 HEAD detached 狀態，意思是「沒有站在任何分支上」。看完記得用 git switch main 回來，不然之後的提交會找不到歸屬。

        
提交編號用 git log --oneline 查，每行最前面那串像 a033373 的就是。

      

    


    
    

      

        
07 · 常見錯誤

        
新手一定會遇到的狀況

        
點開每一題看怎麼解決。

      

      

        

          跳出一堆 # 開頭文字的畫面，不知道怎麼離開
          

            
那是 Vim 編輯器，git commit 沒加 -m 時會打開它讓你寫提交訊息。

            
    
              
  • 想存檔離開：按 Esc，輸入 :wq，按 Enter
    • 
              
  • 不存直接離開：按 Esc，輸入 :q!，按 Enter
    • 
            

            
以後用 git commit -m "說明" 就不會進到 Vim。

          

        

        

          出現 E325: ATTENTION 和 swap file 警告
          

            
代表同一個提交訊息檔已經有另一個 Vim 開著，通常是之前的 git commit 沒關掉。

            
    
              
  • 按 Q 離開警告，找到那個還開著 Vim 的視窗處理掉
    • 
              
  • 找不到的話，關掉所有終端機後刪除殘留檔：rm .git/.COMMIT_EDITMSG.swp
    • 
            

          

        

        

          warning: adding embedded git repository
          

            
你在一個 Git 專案的資料夾裡，又 clone 了另一個專案。外層的專案不會包含裡面那個專案的內容。

            
    
              
  • 取消外層對它的追蹤：git rm --cached 資料夾名
    • 
              
  • 最好把 clone 下來的資料夾移到外面，不要放在另一個專案裡
    • 
            

          

        

        

          HEAD detached at ...
          

            
你正在看某個舊版本，沒有站在任何分支上。這時做的 revert 或 commit 不會進到 main。

            
先用 git switch main 回到分支，再做其他操作。

          

        

        

          已經 commit 了，GitHub 上卻沒有更新
          

            
commit 只存在你的電腦裡，要再執行 git push 才會上傳。

            
    
              
  • 確認你在正確的資料夾：用 git remote -v 看有沒有連到 GitHub
    • 
              
  • 用 git log --oneline 看，origin/main 和 HEAD -> main 在同一行，就代表同步了
    • 
            

          

        

        

          push 時跳出登入視窗，或顯示 403、Permission denied
          

            
第一次 push 需要登入 GitHub，選「Sign in with your browser」即可。

            
出現 403 代表登入的帳號沒有這個 repo 的寫入權限，請確認帳號正確，或請 repo 擁有者把你加為協作者。

          

        

        

          有些檔案我不想被 Git 追蹤（.gitignore）
          

            
在專案最外層建立一個叫 .gitignore 的檔案，每行寫一個要忽略的檔名或資料夾：

            
node_modules/
.DS_Store
*.log
密碼.txt

            
注意：已經被追蹤的檔案，要先 git rm --cached 檔名 才會生效。

          

        

        

          提交訊息要怎麼寫比較好？
          

            
寫「這次做了什麼」，讓未來的自己一眼看懂。

            
    
              
  • ✗ test、update、123
    • 
              
  • ✓ 新增聯絡表單、修正首頁標題錯字
    • 
            

            
一次提交只做一件事，之後要 revert 也比較好處理。
